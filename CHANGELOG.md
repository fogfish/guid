# Changelog

## v3

v3 is a compatibility break. The bit layout is unchanged for `guid.L` — a v2 local value decodes correctly under v3 — but **not for `guid.G`: do not decode a v2 `G` with `FromString` or `FromBase62`.** Neither will error, and both will silently misread ⟨𝒍⟩ and ⟨𝒕⟩, because v3 re-based the drift ladder (see below) and a v2 value's ⟨𝒅⟩ code now indexes a different rung — including v2's own default. Use [`guid.FromV2(isBase62, s)`](v2.go) instead, which decodes with v2's table and re-encodes with v3's. It is migration tooling for this one break, not a permanent part of the API — a free function taking a bool for the encoding, meant to be deleted once v2 keyspaces are gone, not a precedent for the rest of the package's per-type, per-encoding methods.

| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |

| `guid.Z(clock)`                                                          | `guid.ZeroG(clock)` / `guid.ZeroL(clock)`                                                                                        |
| `guid.Time(uid)`, `guid.Node(uid)`, `guid.Seq(uid)`                      | `uid.Time()`, `uid.Node()`, `uid.Seq()`                                                                                          |
| `guid.Before(a, b)`, `guid.After`, `guid.Equal`, `guid.Diff`             | `a.Before(b)`, `a.After(b)`, `a.Equal(b)`, `a.Diff(b)`                                                                           |
| `guid.EpochT(uid)`, `guid.EpochI(uid)`                                   | `uid.Epoch()` — one method, see below                                                                                            |

| `guid.WithUnique(...)`                                                   | removed, see below                                                                                                               |

Four behavioural changes come with it:

* **⟨𝒕⟩ and ⟨𝒔⟩ are always allocated as a pair.** `WithUnique` supplied ⟨𝒔⟩ from a generator independent of ⟨𝒕⟩, which opts out of the coupling that makes values sort in allocation order; it was deprecated in v2 and is gone in v3. `NewClockMock` still pins ⟨𝒕,𝒔⟩ to ⟨0,0⟩ for tests that need a fixed value.
* **⟨𝒅⟩ drift is configured on the clock, not per allocation.** v2 accepted an optional `drift ...time.Duration` on every allocator, while correctness requires the drift to be constant across a keyspace — ⟨𝒅⟩ is the most significant faction, so mixing drifts sorts values by their configuration instead of their time. v3 binds it to `Chronos` with `guid.WithDrift(...)`, which makes the mixed keyspace unrepresentable within one clock. The ladder was also **re-based, not merely extended**: v2 computed `𝑫 = 18 + code` from the 3-bit code stored in ⟨𝒅⟩; v3 reads `𝑫` from a table, `{3,7,11,14,17,21,23,25}`, chosen to spend four rungs below one second rather than above 34 s. The two tables agree at only one of eight codes (`code = 7`, both give `𝑫 = 25`) — every other code, including v2's own default (`code = 3`: v2 meant `𝑫 = 21`, v3 reads `𝑫 = 14`), now names a different window. Since `𝑫` sets where ⟨𝒍⟩ and ⟨𝒕⟩ split, this is not a change in the failover budget alone — it changes which stored bits `Node()` and `Time()` read as which field. **A v2 `G` re-decoded with v3's plain `FromString` or `FromBase62` is silently wrong for seven of its eight possible drift settings**, node and time both, with no error to catch it. `guid.FromV2(isBase62, s)` exists for exactly this — base62.go is otherwise byte-for-byte unchanged between the two versions, so one function covers both of v2's encodings: it decodes with v2's table and re-encodes with v3's, choosing the narrowest v3 rung whose window is at least as wide as v2's, so a migrated keyspace is never less tolerant of clock skew than the one it came from. The old floor of 34.36 s was an artifact of assembling the value with hand-placed shifts, which required ⟨𝒍⟩ to keep `𝑫 - 18` bits above the machine word boundary; the fractions are now placed positionally, so the schema's own range is reachable — that headroom is what the four new sub-second rungs spend.
* **`Epoch` reports wall clock time, whichever way the clock runs.** v2 offered `EpochT` and `EpochI`, and the caller had to know which one matched the clock that allocated the value — picking wrong returned a date centuries off, silently. The direction of a clock is a decision about how the keyspace is laid out, not a fact about the event, so it must not change the reported instant. v3 has a single `uid.Epoch()`: it recovers the domain from ⟨𝒕⟩ itself, since a descending tick is `MaxUint64 - UnixNano` and therefore `>= 2^63` exactly while an ascending one is below it. The discrimination inverts on 2262-04-11, the day `int64` nanoseconds overflow, so it expires with the return type rather than before it. Ordering questions are answered by `Before`, `After` and `Time()` as before.
* **JSON no longer carries a shape marker.** v2 prefixed a local value with `*` so that a `guid.K` could round-trip as either shape. The types are distinct now, so both marshal to a plain 16-character string. v2 JSON containing `*`-prefixed values does not decode.
